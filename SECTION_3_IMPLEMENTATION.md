# РАЗДЕЛ 3. РЕАЛИЗАЦИЯ ПРЕЦЕДЕНТОВ

## 3.8. Увеличение разрешения — ИИ

### 3.8.1. Математическая постановка

Прецедент реализует увеличение разрешения изображений с использованием модели ESRGAN (Enhanced Super-Resolution Generative Adversarial Network). Математическая постановка задачи super-resolution основана на генеративно-состязательной архитектуре.

**Функция потерь генератора (ESRGAN):**

\[
L_G = L_{perceptual} + \lambda_1 L_1 + \lambda_2 L_{RaGAN}
\]

где:
- \(L_{perceptual}\) — перцептуальная функция потерь на основе VGG;
- \(L_1\) — L1-норма разности между сгенерированным и целевым изображением;
- \(L_{RaGAN}\) — состязательная функция потерь для Relativistic GAN;
- \(\lambda_1\), \(\lambda_2\) — весовые коэффициенты.

**Перцептуальная функция потерь:**

\[
L_{perceptual} = \sum_{i=1}^{N} \frac{1}{V_i} \| \phi_i(G(I_{LR})) - \phi_i(I_{HR}) \|_1
\]

где:
- \(I_{LR}\) — входное изображение низкого разрешения;
- \(I_{HR}\) — целевое изображение высокого разрешения;
- \(G(I_{LR})\) — сгенерированное изображение высокого разрешения;
- \(\phi_i\) — i-й слой предобученной VGG сети;
- \(V_i\) — нормализующий фактор для i-го слоя;
- \(N\) — количество слоев.

**Состязательная функция потерь (RaGAN):**

\[
L_{RaGAN} = -E_{x_r}[\log(D_{Ra}(x_r, x_f))] - E_{x_f}[\log(1 - D_{Ra}(x_f, x_r))]
\]

где:
- \(D_{Ra}(x_r, x_f) = \sigma(C(x_r) - E_{x_f}[C(x_f)])\) — relativistic дискриминатор;
- \(x_r\) — реальное изображение;
- \(x_f\) — сгенерированное изображение;
- \(C(x)\) — выход дискриминатора до сигмоиды.

**Нормализация входных данных:**
Модель ожидает входные данные в диапазоне \([0, 255]\) для RGB каналов (float32):
\[
I_{norm} = I_{input}
\]
где \(I_{input}\) — пиксельные значения в диапазоне [0, 255].

**Масштаб увеличения:**
Модель увеличивает разрешение в 4 раза:
\[
H_{out} = 4 \cdot H_{in}, \quad W_{out} = 4 \cdot W_{in}
\]

**Обработка больших изображений (tiling/patching):**
Изображение разбивается на патчи размером \(P \times P\) с перекрытием \(O\):
\[
N_{patches} = \left\lceil \frac{W - O}{P - O} \right\rceil \times \left\lceil \frac{H - O}{P - O} \right\rceil
\]

Для устранения артефактов на границах патчей применяется взвешенное усреднение с косинусной весовой функцией:
\[
w(d) = \begin{cases}
0.5 \cdot (1 - \cos(\pi \cdot d / O)), & \text{если } d < O \\
1.0, & \text{иначе}
\end{cases}
\]

где \(d\) — расстояние до границы патча.

2. **Определение размеров:** Извлекаются размеры входного и выходного тензоров модели для вычисления коэффициента масштабирования.

3. **Разбиение на патчи:** Изображение разбивается на патчи размером 64×64 пикселей с перекрытием 32 пикселя для устранения артефактов на границах.

4. **Параллельная обработка патчей:**
   - Патчи обрабатываются батчами (до 8 параллельно) через корутины Kotlin.
   - Для каждого патча:
     - Извлекается область из исходного изображения.
     - При необходимости выполняется ресайз до размера входного тензора модели.
     - Пиксели конвертируются в формат RGB float32 с диапазоном [0, 255].
     - Выполняется инференс через TFLite Interpreter (с синхронизацией через Mutex).
     - Выходной тензор преобразуется обратно в Bitmap.

5. **Сборка результата:**
   - Обработанные патчи собираются в итоговое изображение с использованием взвешенного усреднения на границах перекрытий.
   - Применяется косинусная весовая функция для плавного blending.

**Входные данные:**
- `Bitmap` — исходное изображение низкого разрешения (любого размера);
- `FilterType.UPSCALE` — тип фильтра.

**Выходные данные:**
- `Bitmap?` — изображение высокого разрешения (увеличенное в 4 раза) или `null` в случае ошибки.

**Промежуточные структуры данных:**
- `PatchInfo` — информация о патче (координаты, размеры);
- `ByteBuffer` — буфер для входных/выходных данных тензора;
- `ProcessedPatchResult` — результат обработки патча (Bitmap и метаданные);
- `FloatArray` — массивы для аккумуляции весов при blending.

### 3.8.3. Реализация классов

#### 3.8.3.1. Класс `EsrganImageProcessor`

**Назначение:** Выполняет инференс модели ESRGAN для увеличения разрешения изображений.

**Поля:**
- `interpreter: Interpreter?` — TFLite Interpreter для модели ESRGAN (инжектируется через DI);
- `interpreterMutex: Mutex` — мьютекс для синхронизации доступа к Interpreter (не потокобезопасен);
- `PATCH_SIZE: Int = 64` — размер патча для обработки;
- `OVERLAP: Int = 32` — перекрытие патчей для устранения артефактов;
- `MAX_PARALLEL_PATCHES: Int = 8` — максимальное количество параллельно обрабатываемых патчей.

**Методы:**
- `processImage(bitmap: Bitmap, filterType: FilterType): Bitmap?` (suspend) — основной метод обработки изображения. Разбивает изображение на патчи, выполняет параллельную обработку и собирает результат.
- `processPatch(...): Bitmap?` (suspend, private) — обрабатывает один патч через модель: конвертирует пиксели в формат модели, выполняет инференс, преобразует выходной тензор в Bitmap.

**Зависимости:**
- `org.tensorflow.lite.Interpreter` — для выполнения инференса;
- Kotlin Coroutines (`Dispatchers.Default`, `withContext`) — для асинхронной обработки;
- Kotlin Coroutines Mutex — для синхронизации доступа к Interpreter.

#### 3.8.3.2. Класс `ModelLoader`

**Назначение:** Утилита для загрузки TFLite моделей из assets.

**Методы:**
- `loadModelFile(context: Context, modelPath: String): MappedByteBuffer` — загружает модель из assets;
- `createInterpreter(modelBuffer: MappedByteBuffer): Interpreter` — создает Interpreter с оптимизированными параметрами (количество потоков = количество ядер CPU).

### 3.8.4. Описание контрольного примера

**Входные данные:**
- Исходное изображение: фотография портрета размером 256×256 пикселей, формат PNG, содержит детали лица человека.
- Тип фильтра: `FilterType.UPSCALE`.

**Ожидаемый результат:**
- Изображение размером 1024×1024 пикселя (увеличение в 4 раза).
- Сохранение деталей исходного изображения.
- Возможны незначительные артефакты на границах патчей (минимизированы через blending).
- Возможны небольшие изменения цветопередачи (характерно для ESRGAN моделей).

**Полученный результат:**
- Изображение успешно обработано, размер соответствует ожидаемому (1024×1024).
- Детали лица сохранены, наблюдается улучшение четкости по сравнению с бикубической интерполяцией.
- На границах патчей артефакты отсутствуют благодаря взвешенному blending.
- Время обработки: ~3.5 секунды на устройстве с 8 ядрами (256×256 → 1024×1024).

**Скриншоты:**
- До обработки: изображение 256×256, видимые пиксели при увеличении.
- После обработки: изображение 1024×1024, плавные переходы, сохранение деталей.

**Примечание о метриках качества:**
Метрики качества (PSNR, SSIM) в текущей реализации не вычисляются автоматически. Для объективной оценки качества обработки рекомендуется использовать эталонные изображения высокого разрешения и сравнивать с результатами модели ESRGAN. Типичные значения PSNR для моделей ESRGAN находятся в диапазоне 25-30 dB, SSIM — 0.80-0.90 (на основе научной литературы).

## 3.9. Шумоподавление — ИИ

### 3.9.1. Математическая постановка

Прецедент реализует удаление шумов с изображений с использованием модели SplitterNet. Задача шумоподавления формулируется как восстановление чистого изображения \(I_{clean}\) из зашумленного \(I_{noisy}\).

**Постановка задачи:**

\[
I_{noisy} = I_{clean} + N
\]

где \(N\) — аддитивный шум (обычно гауссовский).

**Функция потерь для обучения модели (SplitterNet):**
Модель обучается минимизировать разность между предсказанным и целевым изображением:

\[
L = \| \text{SplitterNet}(I_{noisy}) - I_{clean} \|_2^2
\]

**Нормализация входных данных:**
Модель ожидает входные данные в диапазоне \([0, 1]\) для RGB каналов (float32):
\[
I_{norm} = I_{input} / 255.0
\]

**Денормализация выходных данных:**
Выходные данные находятся в диапазоне \([0, 1]\), преобразуются обратно в \([0, 255]\):
\[
I_{output} = I_{model} \cdot 255.0
\]

**Обработка больших изображений (tiling):**
Аналогично ESRGAN, изображение разбивается на патчи размером 256×256 с перекрытием 32 пикселя. При сборке результата применяется гауссово взвешивание на границах:

\[
w(x, y) = \begin{cases}
\min(x, y, W-x, H-y) / border, & \text{если } \min(...) < border \\
1.0, & \text{иначе}
\end{cases}
\]

где \(border = \min(32, W/4, H/4)\) — размер граничной области.

   - Патчи обрабатываются параллельно батчами.
   - Для каждого патча:
     - Если патч меньше 256×256, добавляется паддинг (черные пиксели).
     - Пиксели нормализуются в диапазон [0, 1] (float32).
     - Выполняется инференс.
     - Выходные данные денормализуются обратно в [0, 255].

4. **Сборка результата:**
   - Создаются массивы аккумуляции для каждого канала (R, G, B) и счетчик весов.
   - Для каждого пикселя патча вычисляется вес на основе расстояния до границы.
   - Результаты накапливаются с учетом весов.
   - Выполняется усреднение: `result = accumulated / count`.

**Входные данные:**
- `Bitmap` — зашумленное изображение;
- `FilterType.DENOISE` — тип фильтра.

**Выходные данные:**
- `Bitmap?` — изображение без шумов (того же размера) или `null`.

**Промежуточные структуры данных:**
- `FloatArray` — массивы для аккумуляции результатов по каналам (resultR, resultG, resultB);
- `FloatArray` — массив счетчиков весов (count);
- `Array<FloatArray>` — матрица весов для патча (weights).

## 3.10. Применение художественных стилей — ИИ

### 3.10.1. Математическая постановка

Прецедент реализует стилизацию изображений с использованием моделей типа AnimeGAN2/Hayao для преобразования фотографий в аниме-стиль. Используется архитектура генеративно-состязательной сети (GAN) с перцептуальной функцией потерь.

**Функция потерь генератора (AnimeGAN2):**

\[
L_G = L_{adv} + \lambda_1 L_{con} + \lambda_2 L_{gra} + \lambda_3 L_{col}
\]

где:
- \(L_{adv}\) — состязательная функция потерь;
- \(L_{con}\) — контентная функция потерь (L1);
- \(L_{gra}\) — градиентная функция потерь;
- \(L_{col}\) — цветовая функция потерь;
- \(\lambda_1, \lambda_2, \lambda_3\) — весовые коэффициенты.

**Нормализация входных данных:**
Модель ожидает входные данные в диапазоне \([-1, 1]\):

\[
I_{norm} = (I_{input} / 127.5) - 1.0
\]

**Денормализация выходных данных:**
Выходные данные находятся в диапазоне \([-1, 1]\), преобразуются в \([0, 255]\):

\[
I_{output} = (I_{model} + 1.0) \cdot 127.5
\]

**Поддержка динамических размеров:**
Модели AnimeGAN2 и Hayao поддерживают изображения произвольного размера через `resizeInput()`.

**Обработка фиксированных размеров (Hayao):**
Модель Hayao требует вход 512×512, поэтому изображение масштабируется перед обработкой и восстанавливается после.

**Назначение:** Преобразует Entity в Domain-модель.

**Методы:**
- `toDomain(entity: ProcessingOperationEntity): ProcessingOperation` — преобразует Entity в Domain;
- `toEntity(domain: ProcessingOperation): ProcessingOperationEntity` — преобразует Domain в Entity.

**Особенности:**
- Десериализует `parameters` из JSON строки в объект `OperationParameters`.

#### 3.12.3.7. Компонент `HistoryDetailsBottomSheet`

**Назначение:** Compose UI компонент для отображения детальной информации о записи истории.

**Компоненты:**
- Список операций редактирования;
- Для каждой операции отображается:
  - Название фильтра/операции;
  - Параметры (intensity и др.);
  - Время обработки;
  - Порядковый номер.

### 3.12.4. Описание контрольного примера

**Входные данные:**

## Заключение

В разделе 3 рассмотрены реализации пяти основных прецедентов приложения:

1. **Увеличение разрешения (ESRGAN)** — использует генеративно-состязательную сеть для 4x увеличения разрешения с обработкой патчами и взвешенным blending.

2. **Шумоподавление (SplitterNet)** — удаляет шум с изображений при сохранении деталей, использует гауссово взвешивание при сборке патчей.

3. **Применение художественных стилей (AnimeGAN2/Hayao)** — преобразует фотографии в аниме-стиль с использованием перцептуальных функций потерь.

4. **Просмотр истории обработанных изображений** — обеспечивает реактивное отображение истории через Room Database и Flow.

5. **Просмотр истории операций редактирования** — отображает детальную информацию о каждой операции в рамках сессии редактирования.

Все прецеденты реализованы с соблюдением принципов Clean Architecture, использованием Kotlin Coroutines для асинхронности и Material Design 3 для пользовательского интерфейса.
